# Calendar channels

`beam.calendars.channels` is the lane vocabulary: the named **channels** a calendar's events are
filed under, each with display metadata such as its label. A calendar with one channel reads as a
single document with one column and one feed; a calendar with two or more reads as a multi-lane
timeline.

## Adding a channel

```php
use Splicewire\Beam\Calendars\Registries\ChannelRegistry;

app(ChannelRegistry::class)
    ->register('social', ['label' => 'Social'])
    ->register('press', ['label' => 'Press']);
```

Or set the `channels` array in your published `config/beam/calendars.php`.

## The default lane

The package seeds one channel, `default`. It is an ordinary entry, not a reserved name, so you can
relabel or replace it. If the registry ends up empty, it still answers with `default`: one lane is a
usable calendar, and zero lanes is not. A lane that has been removed still renders, under its raw id.

## Per-tenant lanes

This registry is the default channel source. A multi-tenant host that needs different lanes per
tenant doesn't extend it: it binds `Contracts\ChannelSource` to something tenant-aware, and this
registry remains the fallback.
