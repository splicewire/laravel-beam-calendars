# Calendar event kinds

`beam.calendars.event_kinds` is the vocabulary of what can sit on a calendar date. Each entry maps a
dotted kind key, such as `kind.event` or `kind.run-circuit`, to the Data class its payload is
validated through. The package ships `kind.event`, `kind.series`, `kind.ref` and
`kind.decommission`; an engine or host adds its own.

## Adding a kind

Write a Data class for the payload and register it under its kind:

```php
use Splicewire\Beam\Calendars\Registries\EventKindRegistry;

app(EventKindRegistry::class)->register('kind.launch', LaunchEventData::class);
```

Or add it to the `event_kinds` array in your published `config/beam/calendars.php`. Keys keep their
dots exactly as written. [Splicewire](https://splicewire.test/), for example, adds
`kind.disclosure-ref` and `kind.run-circuit` this way, without the calendar package knowing it
exists.

## Unknown means refused on write

An unregistered kind is simply an absent key, and the write path treats that as the unknown-kind
condition. Writing an event of an unknown kind fails validation, and the message lists every kind
that *is* registered, so you can tell at once whether the package that provides yours is installed.
A known kind's payload is hydrated through its class, which both validates it and stores it in
canonical form.

## Event kinds don't execute

Registering a kind only describes what is stored on a date. To make something run when a date comes
due, register an [action handler](beam.calendars.action_handlers).
